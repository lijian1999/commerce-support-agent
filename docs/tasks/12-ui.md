# 任务 12：Streamlit 聊天界面

先读 `AGENTS.md`，再读 `docs/contracts.md` 的第 2、9 节，以及 `app/state.py`、`app/runner.py`、`cli.py`。本任务新建这些文件：`ui.py`、`tests/test_ui.py`。不要改别的文件。

## 背景

界面是一个薄壳：它和命令行调用同一个入口 `app.runner.run_turn`，只负责展示，不含业务逻辑。页面分三栏：

| 栏 | 内容 |
|---|---|
| 左：侧边栏 | 设置和运行时信息 |
| 中：聊天窗口 | 客户实际看到的内容 |
| 右：执行过程 | 系统内部每一步做了什么 |

`run_turn(graph, ctx, thread_id, text=None, resume=None)` 逐个产出事件：
- `("step", step)`：`step` 有 `name`、`kind`（`model` 或 `code`）、`summary`、`detail`、`notes`（模型的重试、降级记录，通常为空）。
- `("interrupt", preview)`：取消订单在等用户确认。`preview` 有 `action_label`、`order_id`、`order_date`、`status`、`items`（每项 `name`、`quantity`、`price_per_unit`）、`total_amount`、`effect`。恢复时调用 `run_turn(graph, ctx, thread_id, resume={"confirm": True 或 False, "order_id": preview["order_id"]})`。
- `("final", values)`：这一轮结束时的状态。用到的键：`answer`（回复文本，可能为 `None`）、`sources`（引用的文档列表）、`card`（`None`，或 `{"type": "ticket", "ticket_id", "reason_label", "summary", "order_ids", ...}`，或 `{"type": "cancel_result", ...}`）。

## 第一步：会话状态

`st.set_page_config(page_title="电商客服 Agent", layout="wide")` 放在脚本最前面。

`st.session_state` 里的内容（第一次运行或点「新会话」时初始化）：

| 键 | 内容 |
|---|---|
| `graph` | `build_graph(checkpointer=InMemorySaver())`。图和它的 checkpointer 必须放在 `session_state` 里，不能每次重跑脚本时重建，否则对话记录和等待中的确认会丢 |
| `thread_id` | `uuid.uuid4().hex[:8]` |
| `turns` | 列表，每一轮一个字典，见下 |
| `selected` | 右栏当前显示第几轮的步骤（`turns` 的下标）；`None` 表示显示最后一轮 |

一轮的字典：

```python
{"user": 用户消息, "steps": [步骤...], "reply": 回复文本或 None, "sources": [...], "card": 卡片或 None,
 "pending": 等待确认的预览或 None, "decision": None 或 "确认取消" 或 "不取消", "preview": 已处理过的预览或 None}
```

把「初始化会话」写成函数 `reset_session()`：重建 `graph`、换新的 `thread_id`、清空 `turns`、`selected = None`。

## 第二步：侧边栏

依次是：

1. 标题 `st.sidebar.title("电商客服 Agent")`。
2. 「当前登录客户」下拉框（`key="customer"`）：第一项是 `未登录`，后面是 `data/structured/customers.json` 里的全部客户，显示成 `CUST-001 · Sarah Chen`。默认选 `CUST-001` 那一项。切换客户时调用 `reset_session()`（用 `on_change`），因为换了人就是另一个会话。
3. 「模拟故障」下拉框（`key="fault"`）：三项 `关闭`、`主模型不可用`、`主备都不可用`，对应 `fault` 的值 `off`、`primary_down`、`all_down`。
4. 三项只读信息，用 `st.sidebar.caption` 或 `st.sidebar.text`：`今天: <config.DEFAULT_TODAY>`、`知识库线上版本: <版本或 无>`（用 `IndexStore().read_pointer()` 读）、`会话: <thread_id>`。
5. 「新会话」按钮（`key="new_session"`）：点击后 `reset_session()` 再 `st.rerun()`。

每次要跑图时用 `make_context(客户 ID 或 None, None, fault, session_id=thread_id)` 现建一个 Context（客户 ID 是下拉框选项里 ` · ` 前面的部分；选 `未登录` 时为 `None`）。

## 第三步：中间的聊天窗口和右边的执行过程

`chat_col, steps_col = st.columns([3, 2])`。

**聊天窗口**（`chat_col` 里），按 `turns` 的顺序渲染每一轮：
- `st.chat_message("user")` 里写用户消息。
- `st.chat_message("assistant")` 里依次是：
  - 如果这一轮有 `preview`（已经处理过的确认）：渲染预览卡片（见下），卡片下面一行文字 `已选择：<decision>`。
  - 如果这一轮有 `pending`（还在等确认）：渲染预览卡片，下面并排两个按钮 `确认取消`（`key=f"confirm_{下标}"`）和 `不取消`（`key=f"decline_{下标}"`）。
  - `reply` 不为 `None` 时写回复文本。
  - `sources` 非空时用 `st.caption` 写 `引用来源: a.md, b.md`。
  - `card` 的 `type` 是 `ticket` 时渲染工单卡片：`st.container(border=True)` 里依次写 `**人工工单 <ticket_id>**`、`转接原因: <reason_label>`、`涉及订单: <order_ids 用逗号连接，或 无>`、`已附带的对话摘要:` 和 `summary`。
  - 一个按钮 `查看这一轮的步骤`（`key=f"show_{下标}"`），点击后把 `selected` 设为这一轮的下标并 `st.rerun()`。
- 预览卡片：`st.container(border=True)` 里依次写 `**<action_label>**`、`订单 <order_id> · 下单 <order_date> · 状态 <status>`、每件商品一行 `<name> × <quantity>   $<price_per_unit 两位小数>`、`合计 $<total_amount 两位小数>`、`st.warning(effect)`。卡片里的内容全部来自 `preview`，界面不自己拼内容。
- 底部输入框 `st.chat_input("输入消息…", key="chat_input")`。最后一轮有 `pending` 时输入框禁用（`disabled=True`）。

**执行过程**（`steps_col` 里）：
- 小标题 `执行过程`，下面一行 `st.caption` 图例：`🟣 模型   ⚪ 确定性代码   🟡 发生了重试或降级`。
- 显示 `selected` 那一轮（`None` 时是最后一轮）的步骤；还没有任何一轮时写一行 `st.caption("还没有对话")`。再用一行 `st.caption` 写 `第 <n> 轮: <用户消息>`。
- 每个步骤一个 `st.expander`，标题是 `<图标> <name> — <摘要的第一行>`（摘要的第一行超过 60 个字符时截断并加 `…`）。图标：`notes` 非空用 `🟡`，否则 `kind == "model"` 用 `🟣`，`kind == "code"` 用 `⚪`。展开后的内容：完整的摘要用 `st.code(summary, language=None)`；`notes` 非空时每条一行 `st.caption("↻ " + 记录)`；`detail` 不是 `None` 时 `st.json(detail)`。
- 步骤列表下面一行 `st.caption`：`有模型参与的步骤: <n> 个`。

把渲染步骤的代码写成函数 `render_steps(container, turn, index)`，这样跑图的过程中可以反复调用它来刷新。

## 第四步：跑图

写一个函数 `drive(turn, text=None, resume=None)`：

```python
def drive(turn: dict, text: str | None = None, resume=None) -> None:
    ctx = make_context(...)
    for kind, payload in run_turn(st.session_state.graph, ctx, st.session_state.thread_id, text=text, resume=resume):
        if kind == "step":
            turn["steps"].append(payload)
            # 每来一个步骤就刷新右栏，步骤逐条出现
        elif kind == "interrupt":
            turn["pending"] = payload
        elif kind == "final":
            if turn["pending"] is None:
                turn["reply"] = payload.get("answer")
                turn["sources"] = payload.get("sources") or []
                turn["card"] = payload.get("card")
```

- 用户在输入框提交消息时：往 `turns` 追加一轮新的字典，`selected = None`，在聊天窗口里先把这条用户消息显示出来，然后 `drive(turn, text=消息)`，结束后 `st.rerun()`。
- 用户点 `确认取消` 或 `不取消` 时：`preview = turn["pending"]`；把 `turn["pending"]` 设为 `None`、`turn["preview"] = preview`、`turn["decision"]` 设为 `确认取消` 或 `不取消`；然后 `drive(turn, resume={"confirm": True 或 False, "order_id": preview["order_id"]})`，结束后 `st.rerun()`。恢复后产生的步骤接在这一轮已有的步骤后面。
- 步骤逐条出现的做法：在 `steps_col` 里先建一个 `placeholder = st.empty()`，平时用 `render_steps(placeholder.container(), ...)` 渲染；`drive` 里每收到一个步骤就再调一次，整块重画。
- 跑图期间抛出的异常用 `st.error(f"运行出错: {e}")` 显示，不让页面崩掉。
